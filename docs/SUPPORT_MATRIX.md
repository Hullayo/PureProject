# PureProject 2.0.1 支持边界

本矩阵区分文件 / 模型硬限制与实际性能验收。遵守硬限制不代表任意数据分布均能达到交互延迟门槛。

| 维度 | 当前契约 | 说明 |
|---|---:|---|
| 平台 | Windows 10 19041+，x64 | 自包含目录发布 |
| 原生 schema v4 文件 | 256 MiB UTF-8 | 字符串格式导入另有 32 Mi 字符限制 |
| 单项目任务 | 20,000 | 仍受正文与附属数据总量约束 |
| 单包项目 | 2,000 | 同时受总字节预算约束 |
| 交换文件 | 256 MiB | `.pureproject` / `.mm` / `.xlsx` |
| ZIP 展开内容 | 512 MiB | 项目载荷与 manifest 均计入 |
| 单交换项目载荷 | 64 MiB | 过大项目应拆分业务内容或使用原生备份 |
| ZIP 项数 | 4,096 | 不移除 ZIP/XML 资源保护 |
| 新建 / 修改的标题类输入 | 64 个 Unicode 字素 | 项目名、任务 / 子任务标题、任务组名、标签名、里程碑名 |
| 新建 / 修改的长文本输入 | 1,024 个 Unicode 字素 | 项目 / 任务 / 里程碑说明、评论；按全文计数，分段编辑不增加限额 |
| 新建 / 修改的状态名称 | 20 个 Unicode 字素 | 任务状态显示名称 |
| 已有文本、导入与备份 | 按存储契约校验 | 未修改的已有合法值保留原文；项目 / 任务组 / 状态名 500、任务标题 2,000、其他已定义字符串最多 200,000 UTF-16 单元 |
| 撤销历史 | 12 步、200,000 额外任务版本、256 MiB 估算模型权重 | 三者先达到者触发清理，不是进程内存测量 |
| 时间线 | 当前范围最多 500 个任务 | 超出时提示通过筛选缩小范围 |
| 依赖关系图 | 当前范围最多 300 个任务 | 超出时提示通过筛选缩小范围 |

输入长度按完整 Unicode 字素计数，中文、扩展区汉字与组合表情都不会被拆成多个 UTF-16 单元计数。界面显示计数与超限反馈，业务入口在新增或修改时再次校验；超限输入不提交、不静默截断。已有内容未修改时可随其他字段一起保存，实际改写后须符合对应的输入上限；编码长度资源保护始终保留。

项目附加正文（schema 字段 `readme`）随数据保留，当前客户端没有编辑入口，不纳入新增输入限制，遵循存储与交换契约。

**100k 普通文本 A0 与全字段满长 A 是不同负载。** A0 是 10 个项目共 100,000 任务，原生 JSON 约 80.47 MiB；全字段满长 A 的强制文本仅 ASCII 原文就约 56.077 GiB，BMP 中文约 168.232 GiB，超出当前架构。当前支持范围不包含 A，普通文本规模测试的结果也不能作为 A 的验收结论。

若要支持 A，需实现正文与元数据分离、按需读取、事务存储、差量撤销历史、全文索引及一致分卷备份，再开展数据转换、故障恢复与完整规模验证。输入长度限制改善日常输入和显示，不改变存储架构的容量边界。

完整 2+8 小时长稳验收尚未完成。[压力测试记录](STRESS_REMEDIATION_20261006.md) 中的一次十小时测试在约 90.783 分钟因 Private 超过 3 GiB 保护停止，2 小时预压和 8 小时正式长稳均未完成。当前构建需要独立、连续的 2+8 小时验证，不能合并不同运行的时长。验收需同时给出动作延迟、调度心跳、Private / 句柄趋势和全字段完整性。

实际满卷、重启后冷缓存和全部真实 IME / 读屏入口仍需在适用环境分别验证。已有验证记录包含 150% DPI（RasterizationScale=1.5）的标题控件场景，其他 DPI / 布局组合需分别验收。锁屏或工具环境阻塞不得记作通过，原生外部软件保存不能由解析器测试替代。
