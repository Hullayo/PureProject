# 简项原生 2.0.1 支持边界

本矩阵区分文件 / 模型硬限制与实际性能验收。遵守硬限制不代表任意数据分布均能达到交互延迟门槛。

| 维度 | 当前契约 | 说明 |
|---|---:|---|
| 平台 | Windows 10 19041+，x64 | 自包含目录发布 |
| 原生 schema v4 文件 | 256 MiB UTF-8 | 旧字符串格式另有 32 Mi 字符限制 |
| 单项目任务 | 20,000 | 仍受正文与附属数据总量约束 |
| 单包项目 | 2,000 | 同时受总字节预算约束 |
| 交换文件 | 256 MiB | `.pureproject` / `.mm` / `.xlsx` |
| ZIP 展开内容 | 512 MiB | 项目载荷与 manifest 均计入 |
| 单交换项目载荷 | 64 MiB | 过大项目应拆分业务内容或使用原生备份 |
| ZIP 项数 | 4,096 | 不移除 ZIP/XML 资源保护 |
| 新项目名 / 任务标题 | 64 / 128 个 Unicode 字素 | 未改的旧合法值保留；另受 500 / 2,000 UTF-16 单元约束 |
| 说明 / 评论等已定义长文本 | 原契约最多 200,000 UTF-16 单元 | UI 分段不改变存储上限 |
| 历史 | 12 步、200,000 额外任务版本、256 MiB 估算模型权重 | 三者先达到者触发清理，不是进程内存测量 |
| 时间线 / 依赖图密集节点 | 300 个可见节点保护 | 提示缩小范围 |

**100k 普通文本 A0 与全字段满长 A 是不同负载。** A0 是 10 个项目共 100,000 任务，原生 JSON 约 80.47 MiB；原方案 A 的强制文本仅 ASCII 原文就约 56.077 GiB，BMP 中文约 168.232 GiB，超出现有架构。本次没有通过上调常量宣称支持 A。

若要求正式支持 A，需另行实现正文与元数据分离、按需读取、事务存储、差量历史、全文索引及一致分卷备份，再开展迁移、故障恢复与完整规模验证。缩短标题可以改善输入和显示，不能解决数十 GiB 正文架构问题。

修复前十小时尝试在约 90.783 分钟因 Private 超过 3 GiB 保护停止：2 小时预压未完成，8 小时正式长稳未进入。修复后需要全新独立 2+8 小时运行，不能合并旧运行时长。验证需同时给出动作延迟、调度心跳、Private / 句柄趋势和全字段完整性。

实际满卷、重启后冷缓存和全部真实 IME / 读屏入口仍需适用环境分别验证。本轮已观察到 150% DPI（RasterizationScale=1.5）并完成标题控件场景，其他 DPI / 布局组合仍分别验收。锁屏或工具环境阻塞不得记作通过，原生外部软件保存不能由解析器测试替代。
